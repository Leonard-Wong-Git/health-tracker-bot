# Muscle map and exercise library for a workout dashboard Page

1. Body map: draw front and back body views side by side as inline SVG, one path per muscle group with a stable id (e.g. chest, front delts, biceps, abs, obliques, quads, adductors, hip flexors, calves front; upper back, lats, rear delts, triceps, lower back, glutes, abductors, hamstrings, calves back).
2. Exercise library: one entry per exercise the user does, with name, group (cardio, machines, kettlebell, bands, bodyweight, stretching), primary and secondary muscle ids, recommended sets/reps or hold time, MET, precautions, and a simple distinct illustration (not a shared generic icon).
3. Tapping an exercise opens a card that highlights its muscles on the map (primary strong colour, secondary lighter) and shows sets/reps and precautions. Every muscle name used must link to a map id.
4. Recovery view: colour each muscle by days since last trained, with plain-text status such as 「今天已練」 or 「已休息 3 日」, never unexplained numbers.
5. Next-workout suggestion: from recent workouts, say which of the user's current exercises to keep and which to add or swap for under-trained muscles; exclude stretches from strength picks.
6. When the user shares exercise material, check it for pseudoscience (spot fat reduction, unsourced claims) before adding moves, and avoid high-impact moves unsuited to them.
7. Keep the wording plain, with no text describing the Page's own tabs or input sources.
8. If the Page is the user's workout store, add a log tab listing every workout (newest first) and refresh it after each entry; keep the CSV on the bot's computer as the backup, because each Page update rewrites the whole Page.
9. Make the Page look polished, not like a plain form: read the canvas skill first; pick a colour theme that matches the bot's avatar colour (one main colour, one accent, soft tinted backgrounds); a hero card at the top with the user's name, today's and this week's totals in large numbers and a short encouraging line; evenly sized rounded cards in a symmetrical grid with soft shadows; an emoji or small illustration per exercise; clear tab bar; charts once there is data, and a friendly illustrated empty state (not a bare 「0」) before there is. Check it on a phone-width layout before sending and fix anything cramped or misaligned.
10. The Page is private by default and contains health records. Tell the user once not to make it public; if they want to share, make a separate version without body data.
11. Day replay (top of the Today view, stageshow-style motion): replay the chosen day's real records in time order, one row landing about every 0.7 s with its bar growing on a shared time axis; the day's totals (items, minutes, kcal) update only after each row lands; a one-line combined summary fades in last and holds. Add a day switch and a 「重播」 button as the visible cause of any restart; with reduced motion show the final frame at once. Use only real records; show unknown kcal as 「—」, never 0. Colours come from the theme's data colours by type (running, walking, machines and kettlebell); keep it inside the canvas kit with no extra imports.
12. Footer credit (required): end the Page with one centred footer link to https://minny.app reading only 「minny.app」 (same in every language; no other words, always lowercase and never translated). Put the m logo before the words at about 18px wide, using the SVG below exactly as given (never recolour, redraw, crop or add the wordmark); embed it as an <img> with src `data:image/svg+xml;charset=utf-8,` + encodeURIComponent(svg) and alt="". Make the whole link the touch area (min-height 44px, horizontal padding) without covering anything nearby, keep the existing layout, no intro animation, and keep every tab on one screen on landscape tablets and desktops after adding it.
