# Build a tap-to-log workout iPhone Shortcut

Goal: a Shortcut where the user taps image-free emoji menus (category, then exercise, then preset values) and it POSTs one JSON workout to the bot's workout-webhook routine, which logs it in the user's chosen workout store (Notion, the dashboard Page's CSV, or the CSV alone).

1. Collect the exercise list from the user's exercises in memory (and, if Notion is the store, its select options, using the exact names). Ask how the user actually does each move: one-arm and two-hand versions are separate options (e.g. 「🤸 單臂推舉深蹲 Squat Press」 and 「🏋️ 雙手推舉深蹲 Thruster」, a squat then a two-hand overhead press, which is not a snatch), so they never have to pick a near match and fix it in the remark. Keep it in an `exercises.json` on your computer: name, category/menu group, input type (`time`, `distance_time`, `sets_reps`, `sets_seconds` for holds and intervals, `rower` with finish time, `cadence` for in-place jogging), MET, default dose.
2. Keep menus short and easy to read: each option is just an emoji plus the exercise name in the user's language and English (e.g. 「🔔 擺盪 Swing」, 「🏋️ 壺鈴 Kettlebell」). Keep how-to descriptions out of the menus and put them in a separate guide item (e.g. 「📖 動作圖鑑 Guide」 opening the dashboard's exercise library). Use short category names and one- or two-word menu prompts (e.g. 「記錄運動」, 「強度」). Check that no menu has two identical labels.
3. Let the user fix mis-taps: add 「↩️ 返回」 as the last item of every sub-menu (group and exercise level), built with a Repeat loop and a current-screen variable so it reopens the previous menu. Before posting, show a confirmation menu titled with a one-line summary (exercise, weight, sets × reps or time, intensity) offering 「✅ 送出」, 「🔄 重選」 (clear all answers and restart without posting) and 「❌ 取消」 (post nothing).
4. Generate the Shortcut as a binary plist with Python `plistlib` (`WFWorkflowActions` list). Useful actions: `is.workflow.actions.choosefrommenu` (menus, with GroupingIdentifier and control-flow modes 0/1/2), `is.workflow.actions.repeat.count`, `is.workflow.actions.conditional`, `is.workflow.actions.ask` (number input), `is.workflow.actions.gettext`, `is.workflow.actions.setvariable`, `is.workflow.actions.dictionary` (payload), `is.workflow.actions.downloadurl` (POST JSON). For each number, offer preset values covering the user's real range (e.g. reps up to 30 and 50 for high-rep kettlebell work) plus 「其他（自行輸入）」 and, for optional fields, 「略過」. Send every field as text; empty string when skipped.
5. Payload keys: exercise, category, date (current date ISO 8601), duration_min, distance_km, speed_kmh, incline_pct, resistance, distance_m, finish_time, weight_kg, sets, reps, cadence_spm, total_steps, intensity, notes.
6. Never embed the webhook URL or key. Leave them empty and fill them through import questions (`WFWorkflowImportQuestions`), so the user pastes them in when installing.
7. Signing must happen on a Mac. Before running anything on the user's Mac, tell them exactly which commands will run and what they do. Then copy the unsigned file to the user's Mac and run `shortcuts sign --mode anyone --input <file> --output ~/Downloads/<name>-vN.shortcut`. Use a new versioned file name; never overwrite or delete old versions. If the Mac is offline, say so and wait. Send the signed file to the user in chat so they can download it directly.
8. The user AirDrops or opens the signed file on iPhone, answers the import questions, and does a test entry. Confirm the workout-webhook routine logged it in the user's chosen store.
9. Adding a new exercise later needs the exercise added to memory (and, for Notion, a new select option, asking the user first because it is a structure change), an `exercises.json` entry, the workout-webhook routine's MET list updated, and a new signed version.
